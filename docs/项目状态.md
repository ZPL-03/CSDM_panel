## 主流程

```text
用户输入
  -> 规则解析任务，保留 user_input_facts
  -> 候选生成
       -> LLM + 外部知识库/知识图谱
          LLM 输出工程自然语言候选表，系统解析为候选并保留回答原文
       -> CASE_TRANSFER
          结构化案例过滤，案例记忆向量排序辅助
       -> DOE
          参数采样与候选池补足
  -> 代理模型初筛
  -> 真实 ABAQUS 校核
  -> 知识回流
       -> data/cases/ 保存全部校核档案
       -> knowledge/case_library/ 保存满足正式入库条件的案例
       -> csdm_case_memory 写入案例记忆索引
  -> 报告生成
```

候选池总数和初筛保留数量由自然语言需求明确给出。候选来源初始比例来自 `pipeline.candidate_source_ratio`：

```yaml
llm: 2
case_transfer: 1
doe: 1
```

候选池目标为 12 时，初始配额为 LLM 6 个、案例迁移 3 个、DOE 3 个。自然语言同时指定多种筋型时，各来源配额继续按筋型拆分。某一路径不足时由 DOE 补足候选池，所有候选在进入下游前仍需经过规则检查。

## 数据边界

### 任务

任务记录写入 `data/tasks/TASK_*.json`，包括 `task_id`、创建时间、来源和规范化 `task`。`task.user_input_facts` 只描述用户明确输入的事实；候选池总数和初筛保留数量是流程控制事实，缺失时任务不启动。

### 候选

候选使用会话内 `TMP_<n>` 身份，包含来源、筋型、几何、铺层、材料、载荷、边界、设计目标、规则检查和初筛字段。LLM 候选先由自然语言表格解析，再补齐当前任务约束。
LLM、案例迁移和 DOE 三路候选按材料、几何变量和铺层表达式去重；结构等价的重复方案不进入候选池，候选池缺口由 DOE 补足。

### 案例

`data/cases/CASE_<n>.json` 是校核档案。`knowledge/case_library/` 是正式案例库。案例迁移读取案例设计和校核结果，不把历史案例原文送入 LLM。

## 代理模型与校核

- `models/surrogate_metrics.json` 当前选中代理模型为 `mlp`。
- 当前代理模型训练样本数为 350。
- `FEM_AGENT` 只运行真实 ABAQUS 链路。Abaqus 不可用或求解失败时返回结构化失败结果，不生成替代性假结果。
