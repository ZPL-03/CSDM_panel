# 物理模型运行与验收

## 目的

本指南用于运行 T、BLADE、L、HAT 四种筋型的物理层序对照、网格与力学验收，以及外部 API 参与的设计流程。验收对象包括输入约束、复合壳截面、载荷与支承、连接、Abaqus 求解结果、代理选择记录和报告事实。

## 模型假设

- 分析采用理想结构的线性特征值屈曲模型。筋条与蒙皮通过 Tie 理想连接；胶层、紧固件质量、几何缺陷、材料损伤和非线性极限承载不在此模型内。
- 复合壳截面接口为 `CompositeShellSection` 与 `SectionLayer`，单层材料采用 `LAMINA`。求解使用 N、mm 一致单位制，材料输入中的 GPa 模量转换为 MPa。
- 零度方向为部件局部 X 轴，物理层序从局部壳负法向面到正法向面排列。部件绕 X 轴装配旋转时保留轴向；对称层序只展开一次。
- 面内载荷作用于蒙皮四边。以正 `Nx` 表示轴向压缩、正 `Nxy` 表示剪切时，X0、X1、Y0、Y1 边的 `(tx,ty)` 分别为 `(Nx,-Nxy)`、`(-Nx,Nxy)`、`(-Nxy,0)`、`(Nxy,0)`。输入 `kN/m` 与求解单位 `N/mm` 数值相同。节点载荷按相邻边线段半长积分，角点合并两条边的贡献。
- SSSS 四边仅约束 `u3`；SSCC 在 Y0、Y1 边同时约束 `ur1/ur2`；CCCC 四边同时约束 `ur1/ur2`。膜内刚体锚点为原点 `u1=u2=0`、`(L,0)` 点 `u2=0`，不沿边固定膜内位移，不约束 `ur3`。装配集合为 `Edge_X0`、`Edge_X1`、`Edge_Y0`、`Edge_Y1`、`Anchor_Origin`、`Anchor_Axis`。
- 蒙皮中面为 `z=0`，翼缘中面为 `z=(skin_thickness+flange_thickness)/2`，腹板底边与翼缘中面相交；BLADE 腹板底边位于 `z=0`，HAT 帽顶中面位于翼缘中面加筋高处。Tie 关闭调整和厚度影响，显式位置容差为连接中面距离加几何容差，不随网格尺寸变化。
- 各部件可分别指定层序和单层厚度。未提供单层厚度数组时，按物理层数等分部件总厚度；预浸料厚度规格通过显式层厚数组输入。
- 结构化候选支持用户在 `material_system.G13_GPa`、`material_system.G23_GPa` 中提供横向剪切模量。未提供时分别采用 `G13=G12`、`G23=E2/[2(1+0.35)]`；这些缺省关系是建模假设，不是材料实测值，应结合所用材料确定是否适用。
- 面密度按各部件中面面积、厚度和材料密度计算。模态位移是特征向量幅值，不是工作载荷下的位移响应。

## 输入与输出

### 结构化输入

| 输入 | 约束 |
|---|---|
| 几何、载荷、边界 | 用户固定参数贯穿候选、规则、预筛和 FEM；边界类型为 SSSS、SSCC 或 CCCC |
| `skin_layup` | 默认部件层序；`web_layup`、`flange_layup`、`cap_layup` 可分别覆盖 |
| `<component>_ply_thicknesses_mm` | 每项为有限正数，数量等于对应物理层数，总和等于部件几何厚度 |
| `material_system` | 单层弹性参数和密度；可显式提供 `G13_GPa`、`G23_GPa` |
| `analysis.mesh_size_mm` | 有限正网格尺寸；mechanics 使用 `--mesh-sizes-mm` 指定三档尺寸 |
| `--output-dir` | 必须是尚不存在的目录；每次运行使用独立目录 |

### 结果字段

| 字段 | 含义 |
|---|---|
| `BLF_global` | 首个正屈曲特征值，无量纲；字段名称不表示已完成整体模态识别 |
| `second_positive_BLF` | 第二个正屈曲特征值；没有对应值时为 `null` |
| `BLF_local`、`failure_mode` | 未完成模态分类时为 `null` |
| `weight_kg_per_m2` | 模型面密度，单位 kg/m² |
| `status`、`verdict` | 求解状态与目标 BLF 判定；失败或未求解时承载结论为未知 |

### 运行目录

验证入口使用独立的任务、案例、Chroma、报告和求解目录，按筋型复制代理资产并只读访问知识包。

| 输出 | 内容 |
|---|---|
| `acceptance.json` | 运行状态、时间、代码与模型指纹、检查结果和异常信息；`code_sha256` 的相对路径键统一使用 `/` |
| `mechanics.json` | 网格与工况矩阵、逐作业状态、INP/ODB 检查、两对网格差异、复用来源及可选静力结果 |
| `existing_checks/`、`job_checks/` | 历史与当前 ODB 的只读提取脚本、日志、警告节点集和特征值 |
| `static/` | 选择 `--static-check` 时生成的独立静力 INP、ODB、求解日志及反力平衡结果 |
| `data/abaqus_runs/` | 候选输入、建模与求解工件；具体 INP、ODB 和日志路径见结果记录 |
| `data/results/*_layup_comparison.json` | 各筋型配对结果、INP 检查和 BLF 相对变化 |
| `data/results/<TASK_ID>/overall_design_report.md`、`.pdf`、`_facts.json` | 总体方案报告、完整事实、推荐排序和模型解释审计 |
| `api_calls.json` | API 流程的提示词、请求参数、返回正文、结束原因和服务返回的 token 用量；不记录密钥 |
| `data/tasks/screening/`、`data/cases/` | API 流程的候选选择决策及案例记录 |

## 运行条件

| 对象 | 要求 |
|---|---|
| 项目目录 | `core/`、`agents/`、`abaqus/`、`scripts/` 和配置属于同一部署版本；Abaqus 运行时能够加载 `core/laminate.py` |
| Python | 使用 Conda `AGENT` 环境，通过 `conda run -n AGENT` 或 `scripts/start.ps1` 启动，以设置依赖和 DLL 搜索路径 |
| 嵌入与知识库 | API 流程使用 `rag.embedding_device: cpu`、BGE-M3 本地缓存和 `knowledge/external/`。CPU 模式显式指定设备，不探测 CUDA；层序与 mechanics 模式不执行知识检索 |
| 外部 LLM | API 模式使用项目 DeepSeek 配置，模型为 `deepseek-flash`、`thinking.type=disabled`；`URL`、`API_KEY`、`MODEL_NAME` 由进程环境或项目 `.env` 提供。层序与 mechanics 模式不调用 API |
| Abaqus | `ABAQUS_COMMAND` 可解析，许可证可用；部署版本支持 `CompositeShellSection`、`SectionLayer` 和材料方向接口，兼容性通过实际建模与求解检查 |
| 代理模型 | 特征契约 `panel-physical-v3-type-isolated` 为 101 维，四种筋型独立训练并存放于 `models/<筋型>/`；类型不符或版本不兼容时拒绝预测。API 流程按 `unavailable_surrogate_policy` 选择 `direct_fem` 或 `stop` 并记录决策；层序与 mechanics 模式直接调用 FEM，不依赖代理权重，`models/` 可为空 |

代理自动重训默认关闭。特征及其实现、求解实现、训练来源和权重分别绑定指纹。启用代理需完成独立 FEM 记录验收，按筋型、工况和边界统计误差；独立验收记录与训练、留出集合的物理设计分离。验收负责人指定 `--max-mape`、`--max-relative-error` 和 `--min-per-slice`。训练样本包络用于域外拦截。

## 操作命令

以下 PowerShell 命令在项目根目录执行。层序、mechanics 和 API 模式均会调用真实 Abaqus，应按可用许可证和计算资源安排。各模式使用独立输出目录；已有目录不覆盖。

### 环境检查

检查依赖和配置，不调用外部 LLM 或求解器：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -CheckEnvironment
```

该执行策略只作用于启动进程，不修改机器或用户策略。

### 跨版本工件

ODB 和 CAE 使用 Abaqus 版本相关的二进制格式。读取端须实际打开文件确认兼容性；文件传输哈希一致不能证明旧版本程序可读取较新版本工件。

CAE 数据库打开过程可能写入数据库管理信息。核验时打开正式 CAE 的字节副本，导出 INP 对照物理定义，并检查正式文件前后哈希；ODB 使用只读方式打开。

没有兼容读取端时，保留原 INP，在目标版本独立作业目录中用该 INP 求解，并从目标版本 ODB 提取结果。CAE 可由目标版本 `ModelFromInputFile` 导入同一 INP 后保存，属于孤立网格模型。不得仅改文件名、路径或版本标签表示完成转换。

版本对照记录源与目标 Abaqus 版本、命令、INP/ODB/CAE 哈希、物理契约、两次 BLF 及相对差。INP 的层厚、角度、材料、牵引、约束和 Tie 检查分别通过；目标 ODB 不得包含非空连接失败节点集。目标工件和结果通过检查后，才替换对应运行目录、案例记录与检索索引。原 INP 和源版本的保留副本不改写。求解代码指纹表示代码身份，不能替代 Abaqus 可执行程序版本。

### 物理层序对照

四筋型共八个作业。每对保持几何、材料、边界、载荷及总厚度一致，分别使用 `[0/45/-45/90]s` 和 `[90/45/-45/0]s`：

```powershell
$validationRoot = Join-Path (Split-Path -Parent (Get-Location).Path) 'CSDM_panel_validation'
conda run -n AGENT --no-capture-output python -X utf8 -B scripts/validate_physical_workflow.py --mode layup --stiffener-types T BLADE L HAT --output-dir "$validationRoot\ply-01"
```

可缩短 `--stiffener-types` 列表，只运行指定筋型。重跑时指定尚不存在的输出目录，保留失败记录。

### 网格与力学验收

默认方案为四筋型各三档网格 `18/12/8 mm`。每种筋型固定几何、材料、层序 `[0/45/-45/90]s`、SSSS 边界和 `Nx=120 kN/m`，仅改变网格尺寸。T 型细网格另覆盖三种边界与压缩、剪切、压剪的九项矩阵，压缩采用 `Nx=120 kN/m`，剪切采用 `Nxy=60 kN/m`，压剪同时采用这两个值。

T 型细网格 SSSS 压缩基准在矩阵与收敛检查之间共享，因此默认共 20 个独立屈曲任务。下面的命令只调用 FEM 和 ODB 后处理，不调用 LLM：

```powershell
conda run -n AGENT --no-capture-output python -X utf8 -B scripts/validate_physical_workflow.py --mode mechanics --mesh-sizes-mm 18 12 8 --convergence-rtol 0.05 --output-dir "$validationRoot\mechanics-01"
```

该命令执行 20 个独立屈曲任务，不包含静力检查。验收输出使用项目外的独立目录，记录、输入和工件作为整体保留。

复用已有任务时，`--baseline-run-dir` 从已通过的 `mechanics.json` 读取各筋型的几何、材料、层序和分析参数，仅按命令指定的网格与工况生成检查矩阵，不依赖 DOE 的采样顺序。`--reuse-run-dir` 显式指定候选工件目录，入口重新检查匹配 INP 并只读提取 ODB；未匹配任务独立求解。工件引用必须指向实际可读文件；路径迁移清单只证明归档字节，不代替有效工件路径。

历史清单须为 `passed` 并包含有效建模源码指纹。读取时只在内存中将 `code_sha256` 的路径键 `\` 规范为 `/`；路径冲突且指纹不同则拒绝。历史 JSON、INP、ODB 不回写。建模源码指纹不同时，`--reuse-build-change-reason` 记录实际审查依据；该参数不豁免截面、载荷、边界、连接或 ODB 检查。匹配工件缺少审查依据时停止，不自动重复求解。复用来源、历史与当前指纹均写入 `mechanics.json`。

| 参数 | 作用 |
|---|---|
| `--mesh-sizes-mm 18 12 8` | 三个严格递减的有限正网格尺寸，单位 mm |
| `--convergence-rtol 0.05` | 必须在运行前显式指定；只判定中网格到细网格的相对差异 |
| `--stiffener-types T BLADE L HAT` | 网格收敛筋型集合，默认四种 |
| `--matrix-stiffener-types T` | 边界/载荷矩阵的筋型集合，须属于收敛集合；选四种时为 44 个独立屈曲任务 |
| `--nx-kn-per-m 120 --nxy-kn-per-m 60` | 压缩和剪切参考载荷，均须为有限正数 |
| `--balance-rtol 1e-5` | 力及力矩平衡相对容差 |
| `--force-atol-n 1e-5 --moment-atol-nmm 1e-3` | 力、力矩绝对容差 |
| `--connection-atol-mm 0.01` | 中面位置及连接距离的几何检查容差 |
| `--reuse-run-dir <目录>` | 可重复指定；读取匹配工件且保持历史目录不变 |
| `--baseline-run-dir <目录>` | 从已通过的 mechanics 记录固定物理设计；复用已有作业时必须指定 |
| `--static-check` | 对矩阵中的独立工况追加静力反力检查；默认 T 矩阵为九个静力作业，四筋型矩阵为 36 个 |

需要静力平衡时，在同一条 mechanics 命令中追加 `--static-check`，并使用未存在的输出目录。静力 INP 由已通过检查的屈曲 INP 派生，保留模型、初始约束和集中力，采用独立的线性静力步输出 `RF/RM`，不改变生产屈曲定义。未选择该参数时，结果为 `static_status=not_requested`。

### 外部 API 设计流程

默认任务为固定 `360x300 mm`、轴向压缩 `120 kN/m`、两个候选、一个求解名额。流程包含候选生成、筛选、FEM、案例归档和报告。LLM 抽取并由程序核对原文需求，LLM 同时按结构化 JSON 提交候选设计输入；程序校验数量、字段、物理约束和来源一致性。报告实际读取完整 RAG/KG，记录采用证据及模型解释状态。

以下示例使用项目 DeepSeek 配置，并清除当前 PowerShell 进程中的请求参数覆盖值：

```powershell
$env:CSDM_PANEL_LLM_EXTRA_BODY = $null
conda run -n AGENT --no-capture-output python -X utf8 -B scripts/validate_physical_workflow.py --mode api --output-dir "$validationRoot\api-01"
```

`--instruction "完整任务"` 可指定其他筋型、载荷或边界，任务中需给出候选数和求解名额。专项分支验证可按需增加以下选项，使用独立输出目录：

| 选项 | 专项通过条件 |
|---|---|
| `--require-llm-explanation` | 报告实际采用通过契约与内容复核的模型工程评议 |

`CSDM_PANEL_LLM_EXTRA_BODY` 接收 JSON 对象并整体覆盖 `backend.extra_body`；切换服务时按该服务协议配置。报告评议的单次输出预算由 `config/llm_config.yaml` 的 `report_explanation.max_output_tokens` 指定。SDK 自动重试关闭，需求格式、证据或明确约束不一致时停止，截断或空正文不采用。API 验收要求实际使用 LLM 需求抽取和非空外部知识上下文。

报告评议使用当前任务的事实标记绑定数值，推荐对象由程序按完整求解证据与目标值确定。模型解释推荐理由、方案间重量与 BLF 余量取舍及影响决策的验证事项；未知引用、手写数值或不一致推荐均拒绝。契约校验与独立提示内容复核按有限次数执行，仍失败则中止报告导出，保存原响应和具体原因。模型复核不能代替工程师审阅。报告正文不包含完整事实清单或内部检索契约 JSON，详见 [工程设计报告](工程设计报告.md)。

Abaqus 2019 的 CAE Python 2 环境使用 `float.__repr__` 序列化 JSON 浮点数，避免 CAE 显示精度改变层厚、材料参数及物理契约指纹。该设置位于独立 CAE 启动器，在导入建模模块前执行；输入、结果和物理契约仍按原始数值严格比对。

## 验收标准

### 入口自动检查

1. `acceptance.json` 的状态为 `passed`，进程退出码为零。异常或中断检查终态、错误类型和对应日志；建模失败时可能尚无求解结果或 ODB。
2. INP 中各部件采用 `COMPOSITE` 截面，层厚、角度和单层材料参数与候选输入一致；截面引用的 `ORIENTATION` 存在，局部零度方向为部件 X 轴，附加转角为零。
3. 层序对照的两次求解均成功，输入中的几何、载荷、材料和总厚度一致。每对满足 `abs(BLF_1-BLF_2)/max(BLF_1,BLF_2) > 1e-6`；此阈值检查层序变化的结果响应，数值精度按下方物理验收执行。
4. API 流程的所选候选均求解成功，Markdown、PDF 和事实 JSON 存在且非空。分别核对候选来源计数、`llm_requirement_used`、`knowledge_used`、`llm_explanation_used`、代理状态和选择决策；专项分支按所选 `--require` 参数判定。

### mechanics 自动判据

1. 固定几何、层序和工况的三档网格分别报告 `BLF18`、`BLF12`、`BLF8`，以及 `abs(BLF18-BLF12)/BLF12`、`abs(BLF12-BLF8)/BLF8`。5% 方案只要求第二项不大于 `0.05`，第一项用于观察趋势。实际蒙皮节点数须随细化严格增加，所有 BLF 必须有限且为正。其他网格尺寸使用相同的相邻细网格分母规则。
2. 从 INP 节点坐标独立积分各边牵引，不调用生产载荷函数作为参考答案。检查逐节点 `fx/fy`、角点累加、整体合力及关于装配原点的合矩。逐节点容差为 `force_atol + balance_rtol*abs(expected_component)`；整体力、矩容差分别按节点载荷模长之和及其乘最大板边长归一化。
3. `Edge_*` 与实际蒙皮边界节点一致，两个锚点各包含指定单节点。Initial 和屈曲载荷工况 1、2 的有效自由度约束均与模型假设完全一致；缺失约束、多余膜内约束或非零位移均失败。
4. 各实例的壳中面高度、轴向范围、部件数量和 Tie 数量符合筋型。Tie 两侧均非空，从属面完整覆盖翼缘面或腹板连接边，节点至主面的距离在显式容差内，所有实例连接到蒙皮；调整、厚度影响、过大容差或网格相关容差不通过。
5. ODB 装配及实例中的 `WarnNodeMiss*`、`WarnNodeUnconnected*`、`ErrNode*` 节点集非空时失败。其他警告节点集保留供核查。新作业结果中的 BLF 与 ODB 首个正特征值一致；求解或检查失败时记录终态，尚未运行的作业保持 `not_run`。
6. 选择静力检查时，ODB 须达到完整参考载荷，反力字段覆盖约束节点。检查 `sum(F)+sum(RF)` 和 `sum(r×F)+sum(r×RF)+sum(RM)`；力及力矩使用相同的绝对加相对容差。整体平衡检查不代替局部应力与连接传力核查。

### 物理验收

1. 以零度、九十度单向板和对称、非对称层合板基准核对 A/B/D、材料方向和层序方向。对称层合板 B 应在数值容差内接近零；相同比例的不同层序允许 D 不同，均衡或对称本身不要求 D16、D26 为零。
2. 查看三档网格的首个正特征值对应模态、相邻模态及连接区域响应，确认数值比较没有混淆不同模态。`mode_shape_check=manual_review_required` 表示入口未自动进行模态匹配；数值收敛通过与模态形态核查分别记录。
3. 查看剪切、压剪和固支工况的膜内应力分布、连接传力及壳法向。INP 合力/合矩和约束检查证明输入满足指定契约，不单独证明局部纯剪切应力场或物理模型精度。
4. 核对材料参数来源，明确采用用户提供的 G13/G23 或缺省横向剪切假设；按实际工艺检查单层厚度、部件层序和连接理想化的适用性。
