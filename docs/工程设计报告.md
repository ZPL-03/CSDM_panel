# 工程设计报告

## 目的与结构

总体报告回答三个问题：哪些候选满足当前计算判据、程序依据哪些可核验结果进行比较、哪些未验证事项会影响选型或工程放行。

- 设计需求与校核依据：载荷、边界、材料、固定尺寸、设计目标和计算范围。
- 全部候选方案与生成依据：候选参数、物理层序、来源和提案理由。提案理由是待验证的设计假设，不是承载结论。
- 预筛与送检依据：区分代理评分、按筋型轮流选样的直接 FEM 和实际送检记录。多筋型任务列出各筋型的送检数和候选数。未送检候选没有 FEM 判定。
- 有限元校核结果：原始结果、成功或失败状态、判定与候选编号的关联。
- 最终推荐设计方案：满足条件的候选比较、推荐判断、方案取舍、决策边界与验证动作。

推荐只针对本任务中完成完整校核且具备目标比较量的候选，不表示全参数域最优。单个可比较结果只能支持条件性选用，不能证明未求解候选的实际性能。

## 职责与证据

程序负责单位、数值、余量、目标排序、通过状态、模态分类覆盖和编号关联。分类覆盖表示有已分类局部屈曲特征值的结果数占成功求解结果数的比例。实际求解设计通过材料、层序、几何、工况、边界和分析指纹绑定；候选提案参数不能替代正式求解输入。

LLM 依据任务事实、全量校核统计和检索证据解释推荐判断。取舍对照采用同一目标排序下的推荐方案与次位方案，输入包含两者的实际校核指标、编号映射和物理输入差异。程序根据已校核输入区分角度层序与逐层厚度，评议通过事实标记引用差异。没有可比方案时，评议说明校核覆盖与排除原因，并在求解成功的情况下比较最大实算 BLF 与推荐下限。全量参数、求解记录与排序保存在报告及事实 JSON，未送检候选不参与实际性能比较。

工程评议响应包含 `recommendation_candidate_id`、`assessment`、`tradeoffs`、`verification`。推荐判断为一段，方案取舍最多一段，验证事项一至四项。每段评议使用 `{{候选编号.指标}}` 或 `{{TASK.指标}}` 绑定本任务的事实，例如 `{{C1.BLF_global}}`。程序从事实表渲染数值、单位和材料牌号；完整原值保存在事实 JSON。评议只读取允许引用的任务事实和比较量。模态分类覆盖由校核结果章节呈现，评议可提出模态识别方法。

契约校验检查字段、推荐编号、事实引用、数值绑定和决策依据。模型依据原稿、当前事实和校验问题定向修复一次，修复结果仍须完整符合响应契约。内容复核检查事实一致性，以及数值、状态和核查动作是否明确关联对象与指标；发现问题时请求一次定向修订。

`config/llm_config.yaml` 中的 `report_explanation.max_output_tokens` 是每次评议请求的输出上限，须为正整数。生成、格式修复、内容复核和修订使用同一预算。上下文容量由所用模型决定；送检规模影响汇总值，不增加评议的逐项候选明细。文献证据按完整证据块提供。

事实 JSON 的 `llm_explanation_audit.call_traces` 按调用顺序记录阶段、模型、输出预算、结束原因、状态和后端返回的 token 用量。请求拒绝或输出未完整结束时中止报告导出，失败事件记录调用链路及可用的 HTTP 状态。

多变量同时变化的方案比较不能证明某一个变量造成性能差异；较小的计算余量只表示更接近当前判据，不能据此断言缺陷敏感性或允许偏差。制造放行、试验认证及实际连接行为需要独立证据。

## 加筋壁板判据

| 项目 | 当前报告使用的证据 | 比较量与余量 | 不支持的结论 |
| --- | --- | --- | --- |
| 线性屈曲校核 | 逐层复合壳、单层 LAMINA 材料、局部材料方向、理想 Tie 连接及 ODB 中的首个正屈曲特征值 | `BLF_global` 为首个正特征值；比较下限为 `max(1, 任务 BLF 下限)`；相对余量 = `BLF_global / 比较下限 - 1` | 线性特征值不是非线性极限强度；未分类模态不能称为整体或局部屈曲；理想 Tie 不能证明连接工艺合格 |
| 目标比较 | 成功求解结果中的面密度和候选几何 | 最小面密度比较面密度；最小重量比较模型质量，等于 `面密度 × 投影面积`；刚度按直接指标比较 | 当前已校核集合内的排序不能证明全参数域最优 |
| 组合载荷 | 同一候选的参考载荷分量和首个正特征值 | 线性临界载荷按同一特征值等比例缩放参考载荷分量，不混用单一分量的独立承载能力 | 不支持材料损伤、初始缺陷敏感性、后屈曲或非线性极限承载结论 |

HAT 帽形加筋的底部连接板位于腹板外侧。几何、层序、材料、载荷和边界均以候选输入及分析契约为准。

## 外部知识证据

评议读取检索片段与图谱关系，选择当前 `evidence_refs` 及 `check_fields`，提出研究对象、材料、铺层、载荷、边界、连接或方法的核查事项。相同核查条件合并，保留所有关联证据编号。核查事项不判断文献条件与当前方案是否相同。同一文献保留一条来源，不同证据块分别定位。检索片段、图谱关系和适用条件保存在事实 JSON。

## 失败与导出

显式关闭 LLM 时，报告保留确定性结果、比较和分析范围，不把模板文字称为模型解释。启用 LLM 时，API 请求、评议契约或独立内容复核失败会中止导出；不使用替代文本覆盖失败。

Markdown、PDF 和事实 JSON 按任务成组导出。审阅时核对原始 FEM、候选排序、数值与单位、评议和引用的对应关系，并检查 PDF 排版。
