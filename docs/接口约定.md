# CSDM 接口约定

## 1. 智能体统一接口

所有智能体统一暴露：

```python
run(input: dict) -> dict
```

公共进度回调同时支持两种形式：

```python
callback(agent_name: str, message: str)
callback(agent_name: str, message: str, event: dict)
```

结构化事件 `event` 建议包含：

- `agent`
- `event_type`
- `message`
- `payload`

## 2. 核心 Schema

- `schemas/task.schema.json`
- `schemas/candidate.schema.json`
- `schemas/abaqus_result.schema.json`
- `schemas/case_record.schema.json`

## 3. 任务契约

### 3.1 `task.load_conditions`

```json
{
  "type": "compression_shear",
  "label": "压剪组合",
  "Nx_kN_per_m": 900.0,
  "Nxy_kN_per_m": 180.0
}
```

支持枚举：

- `axial_compression`
- `in_plane_shear`
- `compression_shear`

### 3.2 `task.boundary_conditions`

```json
{
  "type": "SSCC",
  "label": "X 向简支 + Y 向固支（SSCC）",
  "description": "X0/X1 两边简支，Y0/Y1 两边固支。",
  "simply_supported_edges": ["X0", "X1"],
  "clamped_edges": ["Y0", "Y1"]
}
```

支持枚举：

- `SSSS`
- `CCCC`
- `SSCC`

### 3.3 `task.candidate_generation_preferences`

```json
{
  "total_candidates": 18
}
```

说明：

- 用于定义初始候选池目标数量
- 默认值来自配置 `pipeline.llm_candidates + pipeline.case_transfer_candidates + pipeline.doe_candidates`
- 当前默认值是 `4 + 2 + 4 = 10`
- 可以通过自然语言直接指定，例如“生成 18 个候选”
- 当规则抽取与 LLM 回填冲突时，以规则抽取出的数量为准

### 3.4 `task.screening_preferences`

```json
{
  "top_k_candidates": 6
}
```

说明：

- 用于定义 DNN 初筛后希望保留的样本数
- 默认值来自配置 `pipeline.top_k`
- 可以通过自然语言直接指定，例如“初筛保留 6 个候选”
- 可以与总候选数量独立设置，例如“生成 18 个候选，初筛保留 6 个候选”
- 当规则抽取与 LLM 回填冲突时，以规则抽取出的数量为准

### 3.5 `task.material_system`

任务层保留一个主材料字段，运行策略分两种：

- 用户明确指定材料时：
  - `material_system.is_user_specified = true`
  - LLM、案例迁移和 DOE 都固定使用该材料
  - LLM 回填不得覆盖该材料选择
- 用户未指定材料时：
  - `material_system.is_user_specified = false`
  - 候选生成允许在 `material_db.yaml` 材料库内自动分散取样
  - 候选上的 `material_system` 允许与任务默认材料不同，后续由 `SCREENER` 统一比较

## 4. 候选生成契约

### 4.1 三条候选来源

候选来源 `candidate.source` 当前有三类：

- `LLM`：LLM 生成路径，允许使用文献片段做 Prompt 增强
- `CASE_TRANSFER`：结构化历史案例迁移路径，可使用 Case Memory 向量索引辅助排序，但不依赖文献 RAG
- `DOE`：参数空间采样路径

### 4.2 LLM 路径

LLM 路径的 Prompt 由以下部分组成：

- 当前任务 JSON
- 工况说明
- 边界说明
- 可选材料列表
- 文献依据 snippets
- 输出 JSON 约束

LLM 输出必须只包含候选设计本身，不应输出：

- `case_id`
- `task`
- `abaqus_results`
- `verdict`
- `created_at`

### 4.3 案例迁移路径

历史案例迁移由 `core/case_retriever.py` 负责，采用“结构化硬过滤 + Case Memory 向量排序”的两阶段逻辑。结构化硬过滤基于：

- `stiffener_type`
- `load_conditions.type`
- `boundary_conditions.type`
- 材料体系兼容性
- 几何中心与等效面内载荷相似度
- 历史 BLF 与当前目标 BLF 的接近程度

Case Memory 由 `core/case_memory.py` 负责，作用是把案例记录转成紧凑检索文本并写入 `csdm_case_memory` 集合。该向量索引只用于相似案例召回和排序，不替代上述硬约束；`retrieve_transferable_cases()` 仍只允许迁移状态成功且结论为“通过”的样本。

其中：

- `retrieve_similar_cases()` 用于查找结构相似案例
- `retrieve_transferable_cases()` 只返回可直接迁移的通过样本
- `transfer_candidates()` 输出迁移后的设计候选

### 4.4 DOE 路径

DOE 候选由 `core/doe_sampler.py` 负责生成，要求：

- 候选几何必须位于参数范围内
- 铺层需满足规则检查
- 候选必须通过 `RuleChecker` 的基础合法性校验

## 5. 候选、结果与案例的上下文继承

候选 `candidate` 在进入后续链路前，必须继承当前任务中的：

- `load_conditions`
- `boundary_conditions`
- `design_targets`

候选标准字段至少包括：

- `candidate_id`
- `source`
- `stiffener_type`
- `geometry`
- `layup`
- `material_system`
- `rule_check`
- `rationale`
- `origin_summary`
- `screening_summary`
- `selection_reason`
- `display_name`
- `persistent_candidate_id`

候选材料规则如下：

- 若任务固定材料，则候选直接继承任务材料
- 若任务未固定材料，则候选可以携带各自独立材料体系

ABAQUS 结果 `abaqus_result` 建议携带：

- `load_summary`
- `boundary_summary`
- `diagnosis_summary`
- `mode_eigenvalues`
- `effective_mode_eigenvalues`
- `analysis_flags`
- `visualization_json`
- `artifact_dir`

线性屈曲结果采用：

- 原始 `mode_eigenvalues` 保留实际提取顺序
- `BLF_global` 取首个正特征值
- 若前若干阶为负特征值，则通过 `analysis_flags.negative_modes_skipped` 和 `analysis_flags.first_positive_mode_index` 记录

案例 `case_record` 由两类身份字段与三块主体组成：

- 身份字段：`case_id`、`candidate_id`
- `task`
- `design`
- `abaqus_results`

其中：

- `candidate_id` 标识进入校核链路的设计方案
- `case_id` 标识归档后的案例记录
- `task` 保留任务语义快照，不作为主数据层关联键
- 顶层 `source` 描述归档链路来源，当前主线归档为 `abaqus_auto`
- `design.source` 描述候选生成来源，当前主线只使用 `LLM`、`CASE_TRANSFER`、`DOE`

会话任务编号 `task_id` 仍可存在于运行时任务对象、界面摘要与报告展示中，但不写入候选、工件与案例主数据链路。

## 6. 文献知识库接口

### 6.1 路径约定

文献知识库存放在：

- `knowledge/literature/raw/`
- `knowledge/literature/records/`
- `knowledge/literature/pdfs/`
- `knowledge/literature/texts/`
- `knowledge/literature/markdown/`
- `knowledge/literature/json/`
- `knowledge/literature/images/`
- `knowledge/literature/imports/pdfs/`
- `knowledge/literature/imports/texts/`
- `knowledge/literature/imports/markdown/`
- `knowledge/literature/imports/json/`
- `knowledge/literature/imports/images/`
- `knowledge/literature/manifests/`

### 6.2 文献记录字段

标准化文献记录至少包含：

- `paper_id`
- `source`
- `source_ids`
- `title`
- `abstract`
- `authors`
- `year`
- `venue`
- `topics`
- `concepts`
- `material_domain_tags`
- `citation_count`
- `is_open_access`
- `oa_status`
- `oa_url`
- `oa_pdf_url`
- `landing_page_url`
- `license`
- `retrieved_at`
- `fulltext_status`
- `fulltext_path`
- `fulltext_text_path`
- `fulltext_markdown_path`
- `fulltext_json_path`
- `fulltext_image_dir`
- `parse_backend`
- `parse_ocr`
- `chunk_count`
- `provenance`

### 6.3 文献向量检索

文献向量库集合名默认来自：

- `app_config.yaml -> literature.collection_name`

当前默认值：

- `csdm_literature_corpus`

`core/literature_corpus.py` 对外提供：

- `retrieve_snippets(task, top_k)`
- `format_snippets(task, top_k)`
- `status()`

`core/literature_ingest.py` 对外提供：

- `search_openalex(query, per_page=None)`
- `ingest_queries(queries, download_pdfs=None, parse_pdfs=None, force_pdfs=False)`
- `download_open_access_pdfs(records=None, force=False)`
- `parse_pdfs(records=None, force=False, backend=None, ocr=None)`
- `import_pdf_directory(pdf_dir, parse_pdfs=True, force=False, backend=None, ocr=None)`
- `reindex_from_records()`
- `load_query_groups(config_path)`

解析后端：

- `pymupdf`：默认后端，只抽取 PDF 文字层，不做 OCR，不保证公式 LaTeX。
- `mineru`：调用本机 `mineru` CLI，输出 Markdown、JSON 和图片目录，`--ocr` 控制 MinerU OCR。
- `nougat`：调用本机 `nougat` CLI，输出适合公式论文的 Markdown，适合扫描或公式密集型论文。

机构订阅或学校账号下载的 PDF 不通过自动登录爬虫处理。用户应在浏览器或图书馆工具中合法下载后，通过 `--import-pdf-dir` 导入本地知识库。导入后的 PDF 与解析结果写入 `knowledge/literature/imports/`，与自动下载的开放获取 PDF 分开存放。

## 7. RAG 引擎接口

`core/rag_engine.py` 已从案例专用实现扩展为通用文本向量引擎，支持：

- `upsert_records(records, id_key)`
- `upsert_documents(ids, documents, metadatas=None)`
- `retrieve(query, top_k=5)`
- `query_text(query_text, top_k=5, where=None)`
- `reset_collection()`
- `count()`

当前默认案例记忆集合名：

- `csdm_case_memory`

文献集合名可通过构造参数覆盖。重建案例记忆索引时只重置案例集合，不删除整个 `knowledge/chroma_db`，避免影响文献集合。

## 8. 对话流程事件

当前主流程使用 `core/conversation_flow.py` 中的 `ConversationFlowController`，关键事件包括：

- `conversation_started`
- `task_summary`
- `candidate_summary`
- `confirmation_requested`
- `assistant_commentary`
- `screening_summary`
- `fem_summary`
- `report_summary`
- `conversation_paused`

关键确认节点固定为：

- DNN 初筛前
- FEM 校核前
- 报告导出前

## 9. 数据目录职责

### 9.1 `data/io`

主程序与 ABAQUS 的 JSON 通信层。

- 输入：`data/io/input_{candidate_id}.json`
- 输出：`data/io/result_{candidate_id}.json`

### 9.2 `data/abaqus_runs`

正式样本工件目录：

```text
data/abaqus_runs/C<n>/
├─ candidate_input.json
├─ C<n>.inp
├─ C<n>.odb
└─ C<n>_mode1.json
```

### 9.3 `data/cases`

全部已校核样本的评估档案，是正式案例主数据层的一部分。

### 9.4 `knowledge/case_library`

正式案例库，仅保留当前规则下可进入知识库的案例。

### 9.5 `knowledge/chroma_db`

Chroma 向量库目录，当前包含案例记忆集合和文献集合。案例 JSON 仍是事实源，向量库是检索索引。

### 9.6 `knowledge/literature`

文献知识库目录，供 LLM 候选生成路径检索文献片段使用。

## 10. 标识规则

- 会话任务编号：`TASK_<n>`
- 会话临时候选：`TMP_<n>`
- 正式样本：`C<n>`
- 正式案例：`CASE_<n>`

默认规则：

- `task` 只表达任务语义
- 会话任务编号不参与候选、工件与案例主数据组织
- 候选阶段只使用 `TMP_<n>`
- 只有进入 FEM 时才分配 `C<n>`
- 正式样本与正式案例编号始终按当前目录中的最大编号继续递增
- 临时候选不会消耗正式编号
- `data/io/`、`data/abaqus_runs/`、`data/cases/` 与 `knowledge/case_library/` 围绕 `candidate_id`、`case_id` 组织上下文

## 11. 迁移与批处理入口

仓库提供以下常用入口：

```powershell
D:/anaconda3/envs/GPT/python.exe scripts/migrate_contracts.py --retrain-surrogate
D:/anaconda3/envs/GPT/python.exe scripts/migrate_contracts.py --case-memory-only
D:/anaconda3/envs/GPT/python.exe scripts/rebuild_abaqus_artifacts.py --case-id CASE_1 --force
D:/anaconda3/envs/GPT/python.exe scripts/ingest_literature.py --seed --query-group composite_basics --max-results 20
D:/anaconda3/envs/GPT/python.exe scripts/ingest_literature.py --reindex
```

## 12. 约束

- 主程序与 ABAQUS Python 不跨环境直接 `import` 业务对象
- 跨环境只通过 JSON 文件通信
- 所有失败都必须输出结构化结果
- 案例迁移路径不得把历史案例原文重新拼进 LLM Prompt；历史案例可以进入独立 Case Memory 向量索引辅助召回和排序
- 文献 RAG 只服务于 LLM 候选生成路径
