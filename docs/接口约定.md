# CSDM_panel 接口约定

## 1. 智能体统一接口

所有智能体统一暴露：

```python
run(input: dict) -> dict
```

公共进度回调同时支持两种形式：

```python
callback(agent_name: str, message: str)
callback(agent_name: str, message: str, event: dict)
```

结构化事件 `event` 建议包含：

- `agent`
- `event_type`
- `message`
- `payload`

## 2. 核心 Schema

- `schemas/task.schema.json`
- `schemas/candidate.schema.json`
- `schemas/abaqus_result.schema.json`
- `schemas/case_record.schema.json`

## 3. 任务契约

### 3.1 `task.load_conditions`

```json
{
  "type": "compression_shear",
  "label": "压剪组合",
  "Nx_kN_per_m": 900.0,
  "Nxy_kN_per_m": 180.0
}
```

支持枚举：

- `axial_compression`
- `in_plane_shear`
- `compression_shear`

### 3.2 `task.boundary_conditions`

```json
{
  "type": "SSCC",
  "label": "X 向简支 + Y 向固支（SSCC）",
  "description": "X0/X1 两边简支，Y0/Y1 两边固支。",
  "simply_supported_edges": ["X0", "X1"],
  "clamped_edges": ["Y0", "Y1"]
}
```

支持枚举：

- `SSSS`
- `CCCC`
- `SSCC`

### 3.3 `task.candidate_generation_preferences`

```json
{
  "total_candidates": 18,
  "source_allocation_mode": "ratio",
  "source_ratio": {
    "llm": 2.0,
    "case_transfer": 1.0,
    "doe": 1.0
  }
}
```

说明：

- 用于定义初始候选池目标数量
- 必须由自然语言需求明确指定
- 候选来源比例来自 `pipeline.candidate_source_ratio`
- 当前比例为 `LLM:CASE_TRANSFER:DOE = 2:1:1`
- 自然语言同时指定多种筋型时，`candidate_generation_preferences.stiffener_types` 保存筋型序列，候选生成按该序列在 LLM、案例迁移和 DOE 三条路径内拆分配额
- 当候选池目标为 12 时，初始配额为 LLM 6 个、案例迁移 3 个、DOE 3 个；若 LLM 或案例迁移有效候选不足，DOE 补足总数
- 可以通过自然语言指定，例如“生成 18 个候选”
- 任务解析只记录规则抽取结果；LLM 不参与任务 JSON 回填

### 3.4 `task.screening_preferences`

```json
{
  "top_k_candidates": 6
}
```

说明：

- 用于定义代理模型初筛后希望保留的样本数
- 必须由自然语言需求明确指定，例如“初筛保留 6 个候选”
- 可以与总候选数量独立设置，例如“生成 18 个候选，初筛保留 6 个候选”
- 任务解析只记录规则抽取结果；LLM 不参与任务 JSON 回填

### 3.5 `task.user_input_facts`

`user_input_facts` 只记录用户在自然语言中明确给出的事实，不记录系统默认补全值。

示例：

```json
{
  "explicit_fields": [
    "load_conditions",
    "boundary_conditions",
    "candidate_generation_preferences.total_candidates",
    "screening_preferences.top_k_candidates"
  ],
  "load_conditions": {
    "type": "compression_shear",
    "Nx_kN_per_m": 900.0,
    "Nxy_kN_per_m": 180.0
  },
  "boundary_conditions": {
    "type": "SSCC",
    "label": "X 向简支 + Y 向固支（SSCC）"
  },
  "candidate_generation": {
    "total_candidates": 18,
    "top_k_candidates": 6
  }
}
```

用途：

- 保护用户明确给出的载荷、边界、材料、筋型、目标和数量
- 让 LLM 候选生成区分“用户已给事实”和“系统候选建议值”
- 为报告与案例追溯提供可审计的输入事实摘要

### 3.6 `task.material_system`

任务层保留一个主材料字段，运行策略分两种：

- 用户明确指定材料时：
  - `material_system.is_user_specified = true`
  - LLM、案例迁移和 DOE 都固定使用该材料
  - LLM 回填不得覆盖该材料选择
- 用户未指定材料时：
  - `material_system.is_user_specified = false`
  - 候选生成允许在 `material_db.yaml` 材料库内自动分散取样
  - 候选上的 `material_system` 允许与任务默认材料不同，后续由 `SCREENER` 统一比较

## 4. 候选生成契约

### 4.1 三条候选来源

候选来源 `candidate.source` 当前有三类：

- `LLM`：LLM 生成路径，允许使用外部知识库/知识图谱片段做 Prompt 增强
- `CASE_TRANSFER`：结构化历史案例迁移路径，可使用 Case Memory 向量索引辅助排序，但不依赖外部知识库/知识图谱
- `DOE`：参数空间采样路径

三条来源合并时按材料、几何变量和铺层表达式形成结构等价签名。签名重复的候选不进入候选池，缺口由 DOE 继续补足；会话候选最终重新编号为连续的 `TMP_<n>`。

### 4.2 LLM 路径

LLM 路径的 Prompt 由以下部分组成：

- 当前规范化任务约束
- 用户明确输入事实 `user_input_facts`
- 工况说明
- 边界说明
- 可选材料列表
- 知识库片段与知识图谱关系；启用但资产不完整时明确报错，显式关闭时不注入片段
- 自然语言候选表格式约束

LLM 输出必须是工程自然语言候选表。系统从候选表中解析：

- `geometry`
- `layup`
- `material_system`
- `rationale`
- `origin_summary`
- `llm_output_excerpt`

LLM 输出不应包含：

- `case_id`
- `task`
- `abaqus_results`
- `verdict`
- `created_at`
- JSON 代码块

### 4.3 案例迁移路径

历史案例迁移由 `core/case_retriever.py` 负责，采用“结构化硬过滤 + Case Memory 向量排序”的两阶段逻辑。结构化硬过滤基于：

- `stiffener_type`
- `load_conditions.type`
- `boundary_conditions.type`
- 材料体系兼容性
- 几何中心与等效面内载荷相似度
- 历史 BLF 与当前目标 BLF 的接近程度

Case Memory 由 `core/case_memory.py` 负责，作用是把案例记录转成紧凑检索文本并写入 `csdm_case_memory` 集合。该向量索引只用于相似案例召回和排序，不替代上述硬约束；`retrieve_transferable_cases()` 仍只允许迁移状态成功且结论为“通过”的样本。

其中：

- `retrieve_similar_cases()` 用于查找结构相似案例
- `retrieve_transferable_cases()` 只返回可直接迁移的通过样本
- `transfer_candidates()` 输出迁移后的设计候选

### 4.4 DOE 路径

DOE 候选由 `core/doe_sampler.py` 负责生成，要求：

- 候选几何必须位于参数范围内
- 铺层需满足规则检查
- 候选必须通过 `RuleChecker` 的基础合法性校验

## 5. 候选、结果与案例的上下文继承

候选 `candidate` 在进入后续链路前，必须继承当前任务中的：

- `load_conditions`
- `boundary_conditions`
- `design_targets`

候选标准字段至少包括：

- `candidate_id`
- `display_name`
- `source`
- `stiffener_type`
- `geometry`
- `layup`
- `material_system`
- `rule_check`
- `rationale`
- `origin_summary`
- `llm_output_excerpt`
- `screening_summary`
- `selection_reason`

编号字段约束：

- `candidate_id` 是当前链路使用的候选或正式样本编号
- `display_name` 是必填显示编号；会话候选与 `TMP_<n>` 一致，正式 FEM 输入和案例设计与 `C<n>` 一致
- `persistent_candidate_id` 只在候选进入 FEM、分配 `C<n>` 后写入会话候选，不在 FEM 前保留空字段，也不写入正式 FEM 输入和案例设计

ABAQUS 结果 `abaqus_result` 建议携带：

- `load_summary`
- `boundary_summary`
- `diagnosis_summary`
- `mode_eigenvalues`
- `effective_mode_eigenvalues`
- `analysis_flags`
- `visualization_json`
- `artifact_dir`

线性屈曲结果采用：

- 原始 `mode_eigenvalues` 保留实际提取顺序
- `BLF_global` 取首个正特征值
- 若前若干阶为负特征值，则通过 `analysis_flags.negative_modes_skipped` 和 `analysis_flags.first_positive_mode_index` 记录

案例 `case_record` 由两类身份字段与三块主体组成：

- 身份字段：`case_id`、`candidate_id`
- `task`
- `design`
- `abaqus_results`

会话任务编号 `task_id` 可存在于运行时任务对象、界面摘要、报告展示和新归档案例的可选追溯字段中，但不参与候选、工件、样本和案例编号分配。

## 6. LLM 后端接口

当前只保留单一 OpenAI 兼容 LLM 后端，配置文件为 `config/llm_config.yaml`，运行参数优先来自项目根目录 `.env`：

- `URL`
- `API_KEY`
- `MODEL_NAME`

工作站领域模型接口示例：

```text
URL=https://csllm.ipen03.com/v1
API_KEY=工作站vLLM密钥
MODEL_NAME=csllm
```

`core/llm_backend.py` 对外提供：

- `chat(system_prompt, user_prompt, max_tokens_override=None)`

LLM 只输出工程自然语言候选表；候选结构化由系统解析层完成。

## 7. 外部知识库/知识图谱接口

外部知识库/知识图谱资产存放在：

- `knowledge/external/rag/retrieval_index.sqlite`
- `knowledge/external/kg/entities.jsonl`
- `knowledge/external/kg/relations.compact.jsonl.gz`
- `knowledge/external/kg/kg_stats.json`
- `knowledge/external/provenance/source_metadata.compact.jsonl.gz`
- `knowledge/external/manifest.json`

运行时代码只读取上述项目内知识资产。

`core/domain_knowledge.py` 对外提供：

- `DomainKnowledgeBase.retrieve(task, top_k=None, kg_top_k=None)`
- `DomainKnowledgeBase.format_snippets(task, top_k=None)`
- `DomainKnowledgeBase.status()`

检索逻辑：

- RAG 从只读 SQLite FTS5 索引执行 BM25 召回，以倒数排名融合任务词与筋型聚焦词的结果；正文、公式、表格和有信息量的图片文本均保留原有证据类型
- 相同内容按指纹去重，同一来源最多保留两个片段；来源清单通过 DOI、来源编号和 URL 合并引用
- 知识图谱从实体 JSONL 和压缩关系 JSONL 召回，优先返回引用已命中文本块的关系
- 来源元数据补齐缺失的标题、DOI、URL、年份和出版信息，片段及图谱关系保留证据块编号
- 外部知识功能关闭时返回空上下文；功能启用但资产缺失、JSON 损坏或 SQLite 不可读时明确报错
- `status()` 返回资产可用性、全文索引路径、检索引擎、导出时间和 RAG/KG/来源数量，不执行全文检索

## 8. 文本向量引擎接口

`core/rag_engine.py` 是通用文本向量引擎，当前运行时只作为案例记忆索引底座使用：

- `upsert_records(records, id_key)`
- `upsert_documents(ids, documents, metadatas=None)`
- `retrieve(query, top_k=5)`
- `query_text(query_text, top_k=5, where=None)`
- `reset_collection()`
- `count()`

当前默认案例记忆集合名：

- `csdm_case_memory`

重建案例记忆索引时只重置案例集合，不删除整个 `knowledge/chroma_db`。

案例嵌入模型为 `BAAI/bge-m3`，输出 1024 维归一化向量，模型位于 Hugging Face 用户缓存。模型加载、索引维度、读写和查询错误直接暴露，不使用哈希伪向量或内存集合替代。多字段元数据过滤使用 Chroma 的 `$and` 条件；查询错误不触发集合重建。

## 9. 对话流程事件

当前主流程使用 `core/conversation_flow.py` 中的 `ConversationFlowController`，关键事件包括：

- `conversation_started`
- `task_summary`
- `candidate_summary`
- `confirmation_requested`
- `assistant_commentary`
- `screening_summary`
- `fem_summary`
- `report_summary`
- `conversation_paused`

关键确认节点固定为：

- 代理模型初筛前
- FEM 校核前
- 报告导出前

报告导出以当前已有 FEM 结果为范围。部分候选已经完成校核时，可以导出阶段报告；未校核候选不进入报告的有限元结果章节、结论统计和工程解释输入。

报告区分铺层设计输入与有限元实现：`runtime_build_panel.py` 对蒙皮、腹板、翼缘和帽顶使用均质正交各向异性壳截面，未逐层使用设计铺层。报告不得把铺层顺序、比例对屈曲的影响写成该模型已验证的事实；BLF 小于一时不能宣称已满足完整参考载荷承载要求。

`max_displacement_mm` 保存首个正特征模态的位移向量最大幅值，属于归一化特征向量，不代表实际载荷下的位移响应。模态云图色条只表达该特征向量幅值。

## 10. 数据目录职责

### 10.1 `data/io`

主程序与 ABAQUS 的 JSON 通信层。

- 输入：`data/io/input_{candidate_id}.json`
- 输出：`data/io/result_{candidate_id}.json`

### 10.2 `data/abaqus_runs`

正式样本工件目录：

```text
data/abaqus_runs/C<n>/
├─ candidate_input.json
├─ C<n>.inp
├─ C<n>.odb
└─ C<n>_mode1.json
```

### 10.3 `data/cases`

全部已校核样本的评估档案，是正式案例主数据层的一部分。

### 10.4 `knowledge/case_library`

正式案例库，仅保留当前规则下可进入正式案例库的案例。

### 10.5 `knowledge/chroma_db`

Chroma 向量库目录，当前只包含案例记忆集合。案例 JSON 仍是事实源，向量库是检索索引。

### 10.6 `knowledge/external`

外部知识库/知识图谱资产目录，包含 173228 个 RAG 文本块、2219 个实体、250606 条关系和 1931 条来源元数据。资产清单记录部署文件、字节数、SHA256 与导出时间。目录已被 `.gitignore` 排除；`scripts/sync_external_knowledge.py` 负责校验、部署和项目外归档。

## 11. 标识规则

- 会话任务编号：`TASK_<n>`
- 会话临时候选：`TMP_<n>`
- 正式样本：`C<n>`
- 正式案例：`CASE_<n>`

默认规则：

- `task` 只表达任务语义
- 会话任务编号不参与候选、工件与案例主数据组织
- 候选阶段只使用 `TMP_<n>`
- 只有进入 FEM 时才分配 `C<n>`
- 正式样本与正式案例编号始终按当前目录中的最大编号继续递增
- 临时候选不会消耗正式编号
- `data/io/`、`data/abaqus_runs/`、`data/cases/` 与 `knowledge/case_library/` 围绕 `candidate_id`、`case_id` 组织上下文

## 12. 迁移与批处理入口

仓库提供以下常用入口：

```powershell
python scripts/migrate_contracts.py --retrain-surrogate
python scripts/migrate_contracts.py --case-memory-only
python scripts/rebuild_abaqus_artifacts.py --case-id CASE_1 --force
```

## 13. 约束

- 主程序与 ABAQUS Python 不跨环境直接 `import` 业务对象
- 跨环境只通过 JSON 文件通信
- 所有失败都必须输出结构化结果
- 案例迁移路径不得把历史案例原文重新拼进 LLM Prompt；历史案例可以进入独立 Case Memory 向量索引辅助召回和排序
- 外部知识库/知识图谱只服务于 LLM 候选生成路径
- 外部知识库/知识图谱运行时只读取 `knowledge/external/`
- `ABAQUS_COMMAND` 可覆盖本机 Abaqus 命令路径，运行、自检与真实有限元回归读取同一配置
- LLM 回答必须正常结束且正文非空；长度截断和过滤结果不进入候选或报告
- LLM 候选的铺层比例必须与铺层序列一致，正负角铺层数量必须平衡
- 报告事实来自完整结构化校核数据，LLM 只提供受约束的定性解释，不修改有限元数值或结论
