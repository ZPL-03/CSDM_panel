# CSDM 接口约定

## 1. 智能体统一接口

所有智能体统一暴露：

```python
run(input: dict) -> dict
```

公共进度回调同时支持两种形式：

```python
callback(agent_name: str, message: str)
callback(agent_name: str, message: str, event: dict)
```

其中结构化事件 `event` 建议包含：

- `agent`
- `event_type`
- `message`
- `payload`

## 2. 核心 Schema

- `schemas/task.schema.json`
- `schemas/candidate.schema.json`
- `schemas/abaqus_result.schema.json`
- `schemas/case_record.schema.json`

## 3. 任务契约

### 3.1 `task.load_conditions`

```json
{
  "type": "compression_shear",
  "label": "压剪组合",
  "Nx_kN_per_m": 900.0,
  "Nxy_kN_per_m": 180.0
}
```

支持枚举：

- `axial_compression`
- `in_plane_shear`
- `compression_shear`

### 3.2 `task.boundary_conditions`

```json
{
  "type": "SSCC",
  "label": "X 向简支 + Y 向固支（SSCC）",
  "description": "X0/X1 两边简支，Y0/Y1 两边固支。",
  "simply_supported_edges": ["X0", "X1"],
  "clamped_edges": ["Y0", "Y1"]
}
```

支持枚举：

- `SSSS`
- `CCCC`
- `SSCC`

### 3.3 `task.candidate_generation_preferences`

```json
{
  "total_candidates": 18
}
```

说明：

- 用于定义初始候选池目标数量
- 默认值来自配置 `pipeline.llm_candidates + pipeline.case_transfer_candidates + pipeline.doe_candidates`
- 当前默认值是 `4 + 2 + 4 = 10`
- 可以通过自然语言直接指定，例如“生成 18 个候选”
- 当规则抽取与 LLM 回填冲突时，以规则抽取出的数量为准

### 3.4 `task.screening_preferences`

```json
{
  "top_k_candidates": 6
}
```

说明：

- 用于定义 DNN 初筛后希望保留的样本数
- 默认值来自配置 `pipeline.top_k`
- 可以通过自然语言直接指定，例如“初筛保留 6 个候选”
- 可以和总候选数量独立设置，例如“生成 18 个候选，初筛保留 6 个候选”
- 当规则抽取与 LLM 回填冲突时，以规则抽取出的数量为准

### 3.5 `task.material_system`

当前任务层仍保留一个主材料字段，但运行策略分两种：

- 用户明确指定材料时：
  - `material_system.is_user_specified = true`
  - 候选生成、DOE 和案例迁移都固定使用该材料
- 用户明确指定材料后，LLM 回填不得覆盖该材料选择
- 用户未指定材料时：
  - `material_system.is_user_specified = false`
  - 候选生成允许在 `material_db.yaml` 中的材料库内自动分散取样
  - 候选上的 `material_system` 允许与任务默认材料不同，后续由 `SCREENER` 统一比较和筛选

## 4. 候选、结果与案例的上下文继承

候选 `candidate` 在进入后续链路前，必须继承当前任务中的：

- `task_id`
- `load_conditions`
- `boundary_conditions`
- `design_targets`

候选的 `material_system` 规则如下：

- 若任务固定材料，则候选直接继承任务材料
- 若任务未固定材料，则候选可以携带各自独立的材料体系

ABAQUS 结果 `abaqus_result` 建议携带：

- `load_summary`
- `boundary_summary`
- `diagnosis_summary`
- `mode_eigenvalues`
- `effective_mode_eigenvalues`
- `analysis_flags`
- `visualization_json`
- `artifact_dir`

其中线性屈曲结果当前采用：

- 原始 `mode_eigenvalues` 保留实际提取顺序
- `BLF_global` 取首个正特征值
- 若前若干阶为负特征值，则通过 `analysis_flags.negative_modes_skipped` 和 `analysis_flags.first_positive_mode_index` 记录

案例 `case_record` 由三部分组成：

- `task`
- `design`
- `abaqus_results`

## 5. 对话流程事件

当前主流程使用 UI 无关的 `ConversationFlowController`，关键事件包括：

- `conversation_started`
- `task_summary`
- `candidate_summary`
- `confirmation_requested`
- `assistant_commentary`
- `screening_summary`
- `fem_summary`
- `report_summary`
- `conversation_paused`

关键确认节点固定为：

- DNN 初筛前
- FEM 校核前
- 报告导出前

## 6. 数据目录职责

### 6.1 `data/tasks`

任务台账目录，保存 `TASK_<n>.json`。

### 6.2 `data/io`

主程序与 ABAQUS 的 JSON 通信层。

- 输入：`data/io/input_{candidate_id}.json`
- 输出：`data/io/result_{candidate_id}.json`

### 6.3 `data/abaqus_runs`

正式样本工件目录：

```text
data/abaqus_runs/C<n>/
├─ candidate_input.json
├─ C<n>.inp
├─ C<n>.odb
└─ C<n>_mode1.json
```

### 6.4 `data/cases`

全部已校核样本的评估档案。

### 6.5 `knowledge/case_library`

正式知识库，仅保留当前规则下可进入知识库的案例。

### 6.6 `knowledge/chroma_db`

ChromaDB 本地向量索引目录，供案例检索使用。

## 7. 编号规则

- 任务编号：`TASK_<n>`
- 会话临时候选：`TMP_<n>`
- 正式样本：`C<n>`
- 正式案例：`CASE_<n>`

默认规则：

- 候选阶段只使用 `TMP_<n>`
- 只有进入 FEM 时才分配 `C<n>`
- 正式编号始终以当前目录中的最大编号继续递增
- 历史迁移不重排现有编号

## 8. 迁移与兼容

仓库已提供：

```bat
conda activate GPT
python scripts/migrate_contracts.py --retrain-surrogate
```

该脚本会处理：

- 任务台账 `data/tasks`
- 案例档案 `data/cases`
- 正式知识库 `knowledge/case_library`
- IO JSON `data/io`
- 运行工件输入 `data/abaqus_runs/*/candidate_input.json`
- ChromaDB 重建
- 代理模型可选重训

## 9. 约束

- 主程序与 ABAQUS Python 不跨环境直接 `import` 业务对象
- 跨环境只通过 JSON 文件通信
- 所有失败都必须输出结构化结果
- 不手工修改 ODB/INP 文件名来迁移样本编号
