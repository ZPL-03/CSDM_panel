# CSDM_panel 接口约定

## 任务

`TaskParser.parse_instruction(text)` 返回 `task_id`、`created_at`、`source` 和 `task`。生产环境先由 LLM 抽取 `facts`，每项只含 `field`、`value`、`quote`；引句必须逐字来自用户原文。程序核对字段白名单、数值、mm/kN/m 单位以及明确尺寸、数量、载荷、筋型、边界、材料和 BLF 目标。无效或遗漏的明确约束直接报错。需求原文和抽取证据保存于 `task.requirement_extraction`。

`task` 包含以下有效字段，详细结构以 `schemas/task.schema.json` 为准：

| 字段 | 含义 |
|---|---|
| `application` | 应用对象 |
| `stiffener_type` | 主筋型，T/BLADE/L/HAT |
| `candidate_generation_preferences.stiffener_types` | 允许筋型序列 |
| `candidate_generation_preferences.total_candidates` | 用户明确候选数，1 至 60 |
| `candidate_generation_preferences.source_ratio` | 接受 `llm`、`case_transfer`、`doe`，非负且至少一项为正；默认比例为 `3:1:1` |
| `screening_preferences.top_k_candidates` | 用户明确求解名额，1 至 30 |
| `geometry_envelope`、`fixed_geometry` | 几何包络和固定值，mm |
| `load_conditions` | 类型与非负 `Nx_kN_per_m`、`Nxy_kN_per_m`，不得同时为零 |
| `boundary_conditions` | SSSS、SSCC、CCCC 及实际边集合 |
| `material_system` | 单层弹性模量 GPa、密度 kg/m³ 和材料选择 |
| `layup_constraints` | 允许角度、对称、平衡和最小比例 |
| `design_targets` | 正 BLF 阈值及设计目标 |
| `user_input_facts` | 用户明确事实，与系统默认值分开 |

候选数和求解名额缺失时任务不启动。材料 `is_user_specified=true` 时所有候选固定使用任务材料。`task_payload_from_request()` 统一解包任务；`build_design_constraints()` 产生几何范围、筋型、铺层、载荷和边界约束，固定值不受全局采样范围替换。

## 候选与选择

`CandidateGenAgent.run(task)` 返回准确数量、物理唯一的候选。来源为 `LLM`、`CASE_TRANSFER` 或 `DOE`。可迁移案例不足时，将缺额分配给同筋型 LLM；任务没有 LLM 配额时返回失败。DOE 数量按配额确定。LLM 每批返回 `candidates` 数组，数量等于请求值，候选统一通过几何、材料、铺层与唯一性校验。响应截断或校验失败可按原因有限重试，仍不足时中止。`TMP_<n>` 为会话编号，进入 FEM 时分配正式 `C<n>`，保存 `session_candidate_id`。

候选字段包括 `stiffener_type`、`geometry`、`layup`、`material_system`、载荷、边界、目标、任务约束和规则检查。代理值、评分在未预测时为 `null`。实际物理签名包含筋型、几何、材料实际参数和部件层序/层厚，不以来源文字或显示名去重。

`layup` 使用 `skin_layup`，其他部件可由 `web_layup`、`flange_layup`、`cap_layup` 覆盖；各部件可提供 `<component>_ply_thicknesses_mm`。层厚数组数量等于展开后的层数，总和等于几何总厚度，每项有限且为正。未给数组时按实际层数等分总厚度。铺层比例由 `core/layup.py` 统一派生，±45 合并。

选择结果必须是输入候选的子集且不改变物理输入。结果数量符合任务名额，身份和物理设计均不得重复。`data/tasks/screening/TASK_<n>.json` 保存输入、入选编号、代理状态、实际动作与选择依据。

## 代理

`SurrogateModelManager(stiffener_type=...)` 负责指定筋型的训练、独立验收和裸特征预测。未指定类型的管理器只分发 `predict_candidates()`，按类型分别加载模型并恢复顺序，不能训练混合权重。

四筋型均为 101 维，版本为 `panel-physical-v3-type-isolated`；对应文件位于 `models/T`、`models/BLADE`、`models/L`、`models/HAT`。元数据类型、特征顺序及指纹、求解版本、权重哈希、训练来源、独立证据和适用域必须有效。模型类型与输入独热编码或候选类型不一致时拒绝。

`train_from_records(records)` 至少需要同类型 10 条兼容成功记录、5 个物理设计，按物理设计分组留出。`validate_from_records()` 要求独立设计及显式误差阈值，每个训练工况/边界切片至少两个独立设计。留出误差不替代独立验收，逐特征包络不证明联合参数空间精度。

`SurrogateUnavailable` 包含明确 `status`、`reason`。编排按 `direct_fem` 或 `stop` 执行，不提供假预测。自动重训默认关闭；开启后仍按筋型分别统计和训练，权重必须独立验收才能使用。

## FEM 与案例

`FEMAgent.run(candidate)` 只接受正式编号和有效物理输入。普通调用拒绝覆盖已有输入、INP、ODB 或 CAE。维护入口可显式 `archive_existing=True`，在项目外保留正式原件后重算，不删除原始证据。

成功结果必须具有匹配的 `candidate_id` 和完整 `analysis_contract`。求解失败返回具体状态与日志摘要，不改变设计重试。`BLF_global` 为首个正特征值；未分类的 `BLF_local`、`failure_mode` 为 `null`。`weight_kg_per_m2` 为面密度。失败或未求解的承载结论未知。

`KnowledgeAgent` 将全部评估保存于 `data/cases/CASE_<n>.json`；成功且通过的记录进入正式案例库，其余只归档。案例与求解正式编号一致，中断作业占用编号，编号允许间隔。案例记忆只辅助相似性排序，不替代结构化迁移或物理结果。

## 外部知识

唯一运行资产为 SQLite 全文索引、图谱实体、压缩关系、统计、压缩来源与清单六个文件。启用但资产缺失或损坏时明确报错；关闭功能时返回空上下文。

`DomainKnowledgeBase` 提供 `retrieve()`、`prepare_context()`、`status()`。全文 BM25 与任务/筋型聚焦结果融合，只接受质量版本 3 且可检索的完整块；表格表头、单位、列索引和投影来源必须符合上游证据契约。关系绑定块编号、来源、指纹、类型、用途及适用条件。

`prepare_context()` 返回 `evidence`、`relations`、`sources`、`included_chunk_ids`、`omitted`、`character_count`、`max_context_chars`。每条 `evidence` 保存引用编号、完整证据正文、适用条件、表格契约和出处定位；`relations` 通过 `evidence_ref` 关联证据，`sources` 保存去重文献。按紧凑 JSON 计算证据、关系和来源的字符数，超出预算的块整体排除。相同内容去重，同源最多两个块。来源按 DOI、来源编号和 URL 合并；同名文献副本在已知 DOI、年份不冲突时合并，章节标题不参与文献身份判断。

## LLM 与报告

`LLMBackend.chat(system_prompt, user_prompt, max_tokens_override=None, json_mode=False)` 使用单一 OpenAI 兼容接口。`.env` 配置 `URL`、`API_KEY`、`MODEL_NAME`，请求扩展由 `CSDM_PANEL_LLM_EXTRA_BODY` 整体覆盖。报告请求启用 JSON mode。空正文、非 `stop` 终止和请求异常直接暴露，SDK 不自动重试。

报告生成器接收 `task`、全部 `candidates`、`screened_candidates` 和实际 `results`；工程评议只读取与实际结果绑定的事实、任务校核事实及同一批外部证据。会话编号关联候选阶段快照，正式编号关联求解结果；显示名称不参与身份判断。候选与当前版本求解契约中的材料、几何、层序、工况和边界必须完全一致。

总体报告分为需求与校核依据、全部候选、预筛与送检、有限元结果、最终推荐、外部知识依据。最终推荐包含数值比较、推荐判断、方案取舍与决策所需验证。正文中的几何尺寸最多保留 3 位小数，层厚与铺层比例最多 6 位，BLF、面密度及目标比较值最多 4 位；完整原值用于计算并保存在事实 JSON 中。来源页码只显示上游确认的正整数，0 表示未知。以符合比较条件的 C1 为最小重量推荐方案为例，解释响应为：

```json
{"recommendation_candidate_id":"C1","assessment":"C1 的首个正特征值为 {{C1.BLF_global}}，达到推荐比较下限 {{TASK.required_BLF}}；其模型质量为 {{C1.objective_value}}，据此按最小重量目标推荐 C1。","tradeoffs":[],"verification":["当前采用 {{TASK.analysis_scope}}，应核查实际连接与模型约束是否相符。"]}
```

每段通过 `{{候选编号.指标}}`、`{{TASK.指标}}` 或 `{{E编号}}` 引用事实或检索证据，数值与单位由程序渲染。`assessment` 必须引用推荐方案的 BLF、目标比较值及 BLF 下限。`recommendation_candidate_id` 必须等于程序推荐，没有可推荐方案时为 `null`。未知引用、手写数值、重复 JSON 字段或不一致推荐均拒绝。可比较方案不足两个时不生成方案间取舍。契约修复与内容复核采用有限次数，保留原响应及具体原因；接口失败或评议仍不合格时中止导出，不替代为固定建议。明确关闭 LLM 的离线验证可生成结构化报告，采用标记保持 `false`。契约见 [工程设计报告](工程设计报告.md)。

程序只在当前逐层模型成功求解、BLF 同时达到任务下限与 1.0、目标比较数据完整的方案中推荐。最小重量比较面密度乘以壁板面积得到的质量；最小面密度比较面密度。刚度目标没有直接测量量时不将 BLF 当作刚度排序。

默认目录为 `data/results/<TASK_ID>/`，工件为 `overall_design_report.md`、`overall_design_report.pdf`、`overall_design_report_facts.json`。可显式传入 `output_dir`。返回值包含三个路径、`report_outputs.overall`、`generated_output_keys` 和解释审计。三种文件全部生成后才替换正式文件；PDF 导出失败不会使用旧 PDF 与新正文配对。事实 JSON 保存全部候选、实际结果、推荐排序、完整知识上下文、API 元数据、原始评议及复核记录。界面优先打开当前会话报告，重启后按任务报告时间选择。

## 维护与验证

运行条件、清理范围和操作命令见 README、[案例维护操作](案例维护操作.md) 与 [物理模型与集成验收](物理模型与集成验收.md)。测试使用隔离业务目录，正式知识只读。完整验收应显式 `--run-real-fem`，API 验收必须实际抽取需求、使用知识并生成真实求解和报告。
