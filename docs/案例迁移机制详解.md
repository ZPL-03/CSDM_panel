# 案例迁移（CASE_TRANSFER）机制详解

## 1. 项目与案例迁移的地位

本项目是**CSDM_panel**（复合材料加筋壁板智能设计系统），一个多智能体系统。案例迁移是**三条并行的候选生成路径之一**。

### 三条候选生成路径对比

| 特性 | LLM + 外部知识库/知识图谱 | **案例迁移（CASE_TRANSFER）** | DOE采样 |
|------|-------------|--------------------------|--------|
| **数据源** | 外部知识库/知识图谱，未就绪时不注入额外知识片段 | 历史案例库 `csdm_case_memory` | 参数空间 |
| **生成方式** | LLM创意生成 | 历史案例复用 | 系统采样 |
| **可靠性** | 中等（需LLM准确度） | **高（有FEA验证）** | 低（未验证） |
| **覆盖范围** | 宽（LLM可创意超出范围） | 窄（受历史案例库限制） | 可控（按参数范围） |
| **迁移规则** | 无硬约束 | **严格硬约束（L3级）** | 无约束 |
| **典型数量** | 3-5个 | 2-3个 | 5个 |
| **目标** | 探索新设计空间 | 快速复用通过设计 | 兜底与参数探索 |
| **核心模块** | `DomainKnowledgeBase` | `CaseRetriever` | `DOESampler` |

## 2. 案例迁移的核心概念

### 2.1 数据来源层次

```
┌─────────────────────────────────────────┐
│  ABAQUS 校核后的所有案例                │ (N=350)
│  data/cases/CASE_1.json ~ CASE_350.json │
├─────────────────────────────────────────┤
│  其中通过验证的正式案例                 │ (N=41)
│  knowledge/case_library/CASE_*.json      │
└─────────────────────────────────────────┘
          ↓ 向量化与索引
┌─────────────────────────────────────────┐
│  案例记忆向量库                         │
│  csdm_case_memory (Chroma)              │
│  - 350条向量索引记录                    │
│  - 每条：案例摘要文本 + 元数据          │
│  - 支持语义相似性查询                   │
└─────────────────────────────────────────┘
```

### 2.2 迁移的本质

**不是直接复制，而是：**
1. 从历史案例中**检索**结构相似的通过设计
2. 对其进行**规范化处理**（补充当前任务约束）
3. 重新**验证**（规则检查）
4. 作为新**候选方案**进入下游处理

```python
# 伪代码
for case in retrieve_transferable_cases(task):
    candidate = normalize_candidate(case, task)
    if rule_checker.validate(candidate):
        yield candidate
```

## 3. 迁移规则详解

### 3.1 第一道关卡：可迁移性判定（Transferability Check）

**必须同时满足三个条件：**

```python
def is_transferable(record) -> bool:
    results = record["abaqus_results"]
    design = record["design"]

    # 条件1：ABAQUS 求解成功
    if results["status"] != "success":
        return False

    # 条件2：结构通过验证（verdict = "通过"）
    if results["verdict"] != "通过":
        return False

    # 条件3：设计详情存在且非空
    if not isinstance(design, dict) or not design:
        return False

    return True
```

**作用：** 过滤掉所有失败、求解不完整的案例

**筛选漏斗：**
```
所有案例 (350)
    ↓ (过滤状态不成功的)
ABAQUS成功 (~320)
    ↓ (过滤结论不为"通过"的)
通过验证的 (~280)
    ↓ (过滤没有design的)
可迁移候选 (10-50, 取决于工况/筋型)
```

### 3.2 第二道关卡：L3级匹配（Match Level Filtering）

**匹配等级定义：**

| 等级 | 条件 | 可迁移 |
|------|------|--------|
| **L3** | 筋型 ✓ + 工况 ✓ + 边界 ✓ + 材料 ✓ | **是** |
| L2 | 筋型 ✓ + (工况 ✓ 或 边界 ✓) | 否 |
| L1 | 筋型 ✓ | 否 |
| L0/-1 | 筋型 ✗ | 否 |

**代码逻辑：**

```python
def match_level(task, record) -> int:
    task_type = task["stiffener_type"]      # T, BLADE, HAT, L
    design_type = record["design"]["stiffener_type"]

    # 最严格：筋型必须相同
    if task_type != design_type:
        return -1  # 直接排除

    # 工况比较
    task_load = task["load_conditions"]["type"]     # axial_compression, ...
    design_load = record["design"]["load_conditions"]["type"]
    same_load = (task_load == design_load)

    # 边界比较
    task_boundary = task["boundary_conditions"]["type"]  # SSSS, CCCC, SSCC
    design_boundary = record["design"]["boundary_conditions"]["type"]
    same_boundary = (task_boundary == design_boundary)

    # 材料比较（宽松）
    task_material = task["material_system"]["name"]
    design_material = record["design"]["material_system"]["name"]
    same_material = (not task_material or not design_material
                     or task_material == design_material)

    # 返回匹配等级
    if same_load and same_boundary and same_material:
        return 3  # L3: 完全匹配 ✓✓✓
    if same_load and same_boundary:
        return 2  # L2: 边界匹配 ✓✓
    return -1  # 都不符合
```

**实际例子：**

```
任务：T型筋, 轴压, SSSS, T700/Epoxy

案例1：T型筋 + 轴压 + SSSS + T700/Epoxy
  结果：L3 ✓✓✓ 可以迁移

案例2：T型筋 + 轴压 + SSSS + M21/Epoxy
  结果：L3 ✓✓✓ 可以迁移（材料宽松）

案例3：T型筋 + 轴压 + CCCC + T700/Epoxy
  结果：-1 ✗✗✗ 不可迁移（边界不同）

案例4：BLADE + 轴压 + SSSS + T700/Epoxy
  结果：-1 ✗✗✗ 不可迁移（筋型不同）

案例5：T型筋 + 剪切 + CCCC + T700/Epoxy
  结果：-1 ✗✗✗ 不可迁移（工况和边界都不同）
```

**关键限制：**
- ❌ 无法跨筋型迁移（T型和BLADE是两个完全独立的设计空间）
- ❌ 无法跨工况迁移（轴压和剪切的失效模式完全不同）
- ❌ 无法跨边界迁移（SSSS和CCCC的应力分布完全不同）

### 3.3 第三道关卡：组合评分与排序

**目的：** 在通过L3过滤的2-5个候选中，找出**几何和性能最接近**的

#### 3.3.1 基础评分（Base Score）

```python
def score(task, record) -> float:
    """计算任务与案例之间的距离，分数越低越好"""

    design = record["design"]
    geometry_center = task["geometry_envelope"]  # 目标几何范围的中心

    # 1. 载荷差异（最高权重）
    task_load = equivalent_in_plane_load(task["load_conditions"])
    design_load = equivalent_in_plane_load(design["load_conditions"])
    load_gap = abs(task_load - design_load)

    # 2. 几何尺寸差异
    length_gap = abs(design["geometry"]["panel_length_mm"] - geometry_center["panel_length_mm"])
    width_gap = abs(design["geometry"]["panel_width_mm"] - geometry_center["panel_width_mm"])
    height_gap = abs(design["geometry"]["stiffener_height_mm"] - geometry_center["max_stiffener_height_mm"])

    # 3. 性能目标差异
    target_blf = task["design_targets"]["BLF_min"]
    result_blf = record["abaqus_results"]["BLF_global"]
    blf_gap = abs(result_blf - target_blf)

    # 加权求和（分数越低越好）
    score = (
        load_gap * 1.0           # 载荷差异权重最高
        + length_gap * 0.02      # 几何权重较低
        + width_gap * 0.02
        + height_gap * 0.05
        + blf_gap * 100.0        # BLF权重很高（100倍）
    )
    return score
```

**权重解释：**
- 📌 **load_gap × 1.0** - 载荷差异最重要（工程约束）
- 📌 **blf_gap × 100.0** - BLF性能差异也很重要（意味着设计余度不同）
- 📌 **几何差异 × 0.02-0.05** - 几何次要（可通过微调改进）

**实例计算：**

```
任务：轴压 Nx=500 kN/m, BLF_min=1.5, 几何中心 L=700, W=600, h=40

案例A：Nx=450, L=720, W=610, h=38, BLF_result=1.8
  load_gap = |500-450| = 50
  length_gap = |720-700| = 20
  width_gap = |610-600| = 10
  height_gap = |38-40| = 2
  blf_gap = |1.8-1.5| = 0.3
  score_A = 50*1.0 + 20*0.02 + 10*0.02 + 2*0.05 + 0.3*100.0
          = 50 + 0.4 + 0.2 + 0.1 + 30 = 80.7

案例B：Nx=480, L=750, W=580, h=45, BLF_result=1.6
  load_gap = |500-480| = 20
  length_gap = |750-700| = 50
  width_gap = |580-600| = 20
  height_gap = |45-40| = 5
  blf_gap = |1.6-1.5| = 0.1
  score_B = 20*1.0 + 50*0.02 + 20*0.02 + 5*0.05 + 0.1*100.0
          = 20 + 1.0 + 0.4 + 0.25 + 10 = 31.65

⇒ 案例B更优（31.65 < 80.7）
```

#### 3.3.2 向量排序调整（Vector Rank Adjustment）

```python
def combined_score(base_score, vector_rank, vector_size) -> float:
    """混合评分 = 工程距离 + 向量排名"""

    if vector_rank is None:
        # 向量库未返回此案例，惩罚为列表长度
        return base_score + vector_size * 0.1

    # 向量排名调整（rank=0最优）
    return base_score + vector_rank * 0.1
```

**向量排名的来源：**
1. 系统为每个案例生成**紧凑的摘要文本**（见 `case_memory.py`）
2. Chroma 向量库将摘要**转为向量** → **向量相似性排名**
3. 排名反映**语义相似度**（工程描述的接近程度）

**为何需要向量排序：**
- 纯工程距离无法捕捉所有细节
- 例如：两个案例载荷/几何相同，但材料体系/铺层完全不同
- 向量库补捉这种高层**语义相似性**

#### 3.3.3 最终排序

```python
def rank_candidates(candidates, base_scores, vector_ranks, vector_size):
    """按综合分排序"""

    combined_scores = [
        base_score + (rank if rank is not None else vector_size) * 0.1
        for base_score, rank in zip(base_scores, vector_ranks)
    ]

    # 升序排列（分数越低越好）
    ranked = sorted(
        zip(candidates, combined_scores),
        key=lambda x: x[1]
    )

    return [candidate for candidate, _ in ranked[:top_k]]
```

#### 3.4.1 规范化过程

从选中的案例中**提取design部分**，但进行若干修改：

```python
def normalize_candidate(case, task) -> Dict:
    """将历史案例转换为新的候选方案"""

    raw_design = case["design"]

    # 1. 新建candidate_id
    candidate_id = format_temp_candidate_id(index)  # TMP_1, TMP_2, ...

    # 2. 标记来源
    source = "CASE_TRANSFER"

    # 3. 提取设计参数（几何、铺层、材料）
    geometry = raw_design["geometry"]
    layup = raw_design["layup"]
    material_system = raw_design["material_system"]

    # 4. 补充任务约束（不是来自历史案例）
    load_conditions = task["load_conditions"]     # 用新任务的
    boundary_conditions = task["boundary_conditions"]
    design_targets = task["design_targets"]

    # 5. 生成说明
    rationale = f"参考历史案例 {case['case_id']} 微调生成"

    return {
        "candidate_id": candidate_id,
        "source": "CASE_TRANSFER",
        "stiffener_type": geometry["stiffener_type"],
        "geometry": geometry,
        "layup": layup,
        "material_system": material_system,
        "load_conditions": load_conditions,       # 来自当前任务
        "boundary_conditions": boundary_conditions,  # 来自当前任务
        "design_targets": design_targets,         # 来自当前任务
        "rationale": rationale,
        "rule_check": { ... }  # 待填充
    }
```

#### 3.4.2 规则检查（Rule Validation）

```python
def validate_candidate(candidate):
    """检查候选是否满足工程约束"""

    checks = {
        "geometry_range": check_geometry_bounds(candidate["geometry"]),
        "layup_validity": check_layup_rules(candidate["layup"]),
        "solver_window": check_solver_parameters(candidate),
        "design_feasibility": check_design_targets(candidate),
    }

    is_valid = all(checks.values())

    return {
        "is_valid": is_valid,
        "checks": checks,
        "failures": [k for k, v in checks.items() if not v]
    }
```

## 4. 迁移契约规范化（Data Migration）

### 4.1 目的

历史案例的 JSON 格式可能不一致。`migrate_contracts.py` 负责：
1. 统一格式
2. 补充缺失字段
3. 验证数据完整性

### 4.2 三大规范化函数

#### 4.2.1 `normalize_candidate_document()`

对候选（设计）进行规范化：

```python
def normalize_candidate_document(candidate, task=None) -> Dict:
    """规范化候选文档"""

    normalized = dict(candidate)

    # 1. source 规范化为标准值
    raw_source = str(normalized.get("source", "")).upper()
    normalized["source"] = (
        "LLM" if "LLM" in raw_source
        else "DOE" if "DOE" in raw_source
        else "CASE_TRANSFER" if "CASE" in raw_source
        else "DOE"  # 默认
    )

    # 2. 工况、边界规范化
    normalized["load_conditions"] = normalize_load_conditions(...)
    normalized["boundary_conditions"] = normalize_boundary_conditions(...)

    # 3. 补充默认值
    normalized.setdefault("origin_summary", "")
    normalized.setdefault("display_name", candidate_id)

    return normalized
```

#### 4.2.2 `normalize_result_document()`

对ABAQUS结果进行规范化：

```python
def normalize_result_document(result, design=None) -> Dict:
    """规范化结果文档"""

    normalized = dict(result)

    # 如果缺失诊断文本，自动生成
    if not normalized.get("diagnosis_summary"):
        if normalized.get("status") == "success":
            verdict = normalized.get("verdict", "未判定")
            normalized["diagnosis_summary"] = f"历史结果已迁移，当前结论为"{verdict}"。"
        else:
            normalized["diagnosis_summary"] = "历史结果已迁移，请结合错误日志继续复核。"

    return normalized
```

#### 4.2.3 `normalize_case_record()`

对整个案例记录进行规范化：

```python
def normalize_case_record(record) -> Dict:
    """规范化完整案例记录"""

    normalized = dict(record)

    # 1. 规范化三个主要部分
    normalized["task"] = normalize_task_payload(...)
    normalized["design"] = normalize_candidate_document(...)
    normalized["abaqus_results"] = normalize_result_document(...)

    # 2. 规范化结论
    normalized["verdict"] = (
        normalized.get("verdict")
        or normalized["abaqus_results"].get("verdict")
        or "未知"
    )

    # 3. 移除过时字段
    normalized.pop("task_id", None)
    normalized.pop("request_id", None)

    # 4. 验证完整性
    validate_or_raise("case_record.schema.json", normalized)

    return normalized
```

## 5. 工作流与案例内容

### 5.1 检索可迁移案例的全流程

```
1. 候选生成编排（CandidateGenAgent）
   └─ 调用 _case_transfer_candidates()

2. 案例检索器（CaseRetriever）
   └─ 调用 retrieve_transferable_cases(task, top_k=2)
       ├─ 向量库查询：chroma_db.query(task_text, top_k=8)
       │   └─ 返回 hit_1, hit_2, ..., hit_8（向量排名）
       │
       ├─ 过滤1：可迁移性 is_transferable(record)
       │   └─ status="success" & verdict="通过" & design存在
       │   └─ 通常保留 10-30 个
       │
       ├─ 过滤2：L3级匹配 match_level(task, record) == 3
       │   └─ 筋型 + 工况 + 边界 + 材料全部一致
       │   └─ 通常保留 2-5 个
       │
       ├─ 评分排序
       │   ├─ base_score = load_gap + geometry_gap + blf_gap
       │   ├─ combined_score = base_score + vector_rank * 0.1
       │   └─ 升序排列
       │
       └─ 返回 top_2 记录

3. 规范化与验证（CandidateGenAgent._normalize_candidate）
   ├─ 新建 candidate_id = "TMP_1"
   ├─ source = "CASE_TRANSFER"
   ├─ 补充 load_conditions/boundary_conditions（来自task）
   ├─ 补充 design_targets（来自task）
   ├─ 生成 rationale = "参考历史案例 CASE_XX 微调生成"
   │
   └─ 规则检查 rule_checker.run()
       ├─ 几何范围检查
       ├─ 铺层合理性检查
       └─ is_valid = true/false

4. 结果汇合
   └─ 保留 is_valid=true 的候选
   └─ 失败候选被舍弃
   └─ 与 LLM、DOE 候选合并
```

### 6.2 目标分配逻辑

```python
# 用户要求总共10个候选
target_total = 10

# 按比例分配（若干路径可能失败）
llm_target = round(10 * 3 / (3+2+5)) = 3
case_target = round(10 * 2 / (3+2+5)) = 2
doe_target = round(10 * 5 / (3+2+5)) = 5

# 动态调整（如果某路径没有生成足够数量）
if llm_actual < llm_target:
    doe_target += (llm_target - llm_actual)
if case_actual < case_target:
    doe_target += (case_target - case_actual)

# 最终确保总数 = target_total
```

## 8. 故障排查

### 问题：某任务无法迁移任何案例

**可能原因：**
1. 案例库中无该筋型的通过案例 → 需要重新运行ABAQUS生成
2. 过滤条件过严格 → 考虑放松材料约束
3. 向量库出错 → 重建：`python scripts/migrate_contracts.py --case-memory-only`

**解决方案：**
```bash
# 重建案例记忆索引
python scripts/migrate_contracts.py --case-memory-only

# 检查索引大小
python -c "from core.case_memory import CaseMemoryIndex;
           idx = CaseMemoryIndex();
           print(idx.engine.get_or_create_collection('csdm_case_memory').count())"
```

### 问题：迁移候选验证失败（rule_check.is_valid=false）

**可能原因：**
1. 历史案例的几何参数超出了新的求解器窗口范围
2. 铺层规则更新了，但历史案例还是旧规则
3. 设计目标更严格了，历史案例无法满足

**解决方案：**
- 检查 `rule_check.failures` 字段，了解具体失败项
- 如果历史案例仍有参考价值，可考虑放松某些约束
- 否则，等待DOE补充其他候选

## 9. 总结

| 方面 | 关键点 |
|------|--------|
| **地位** | 三条并行候选生成路径之一，补充LLM+DOE |

| **失败降级** | 无法迁移时，由DOE补充 |
| **关键代码** | `core/case_retriever.py`, `agents/candidate_gen.py`, `scripts/migrate_contracts.py` |
